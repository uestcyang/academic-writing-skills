# 验收案例

这些案例检查编辑行为是否符合任务，不提供“去 AI 率”或作者识别指标。全部材料为合成教学设定，文献代号、实验数字和任务情境均不对应真实研究。

## 执行方法

1. 开启没有项目历史的新对话或 Agent 上下文。
2. 只提供 `skills/academic-writing/SKILL.md` 和 [cases.json](cases.json)，允许按 skill 链接读取参考资料。
3. 逐例提交原始任务与材料，保存完整输出。不要向执行者提供下面的评分要点。
4. 再由审阅者对照材料和评分要点检查结果，记录失败与修正。若修改 skill 后重跑，应注明版本变化。

## 评分要点

| 案例 | 主要检查 |
|---|---|
| C01 | 只把真实完成项写入已有基础，不把流程通畅当作方法有效 |
| C02 | 统计不显著及样本条件完整，没有生成“等效”结论 |
| C03 | 两项文献的贡献分别归属，不补造论文身份或性能结果 |
| C04 | 识别两个因素共同改变，不能宣称独立因果；后续设计保持计划语气 |
| C05 | 必要反驳及其证据仍可表达，不为降词表命中而删去否定 |
| C06 | 只修改指定内容，不重做结构或声称完成未做的文件渲染 |
| C07 | 信息不足时完成有依据的文字，集中指出待补引文，不造出处 |
| C08 | 术语、数字、单位、失败处理和负结果保持准确 |

涉及事实、数值、否定、因果、引用或修改范围的错误视为该例失败。其他措辞选择允许多种正确答案，无需与范文逐字一致。

## 结果能支持什么

少量合成案例可以发现明确的指令缺陷，不能估计真实论文上的总体效果，也不能证明优于其他 skill 或不使用 skill。对自然性和读者理解的评价，需要独立读者、合适的领域材料与预先确定的比较设计。
